## 1. 目標與範圍

### 1.1 目標
各廠（一～四廠、台北）的分機資料，由廠務在網站上維護，系統匯出。**第一階段只做一廠，其他廠區為第二階段（見第 10 節）**；資料模型與畫面從一開始就帶「廠區」欄位，第二階段不必重做。系統匯出：
1. EIP 上傳 Excel（覆蓋整廠）
2. 列印版 1（貼牆版）：對齊現有貼牆分機表，含檔尾撥號規則
3. 列印版 2（新風格）：依部門分區塊的卡片

網頁上也提供查詢（清單／分機表兩種顯示）。

### 1.2 範圍
- 只管分機。欄位：姓名、部門、職稱、市話、分機、簡碼、備註；等級（A/B）記在分機號碼上（見 4.4）。
- 一個系統、多個廠區，用「廠區」欄位區分；各廠有自己的部門表、分機號碼表與匯出格式。第一階段只建一廠的資料。
- 分機不唯一：同一分機可多人使用，不擋。
- 人員、單位、部門一律只停用、不刪除。
- 不做：「最後確認日」提醒、淺色陰影（意義未確認）。

## 2. 使用者與權限

| 角色 | 能做的事 |
|---|---|
| 任何人（內網，**免登入**） | 查詢各廠分機（清單／分機表），唯讀 |
| 該廠廠務（即總務） | 維護自己廠的人員、單位、部門表、分機號碼表、列印版面；處理異動；匯出 |

- **查詢免登入**（2026-11-09 決定）：只有內網連得到 NAS 10.11.1.40（資訊處已設定，訪客 Wi-Fi 連不到），因此不另做網段限制。公開查詢頁只顯示姓名、部門、職稱、分機、等級，不顯示 Email、工號或其他欄位，不提供下載。維護與匯出仍須 AD 登入並屬於該廠廠務群組。
- 維護權限依廠區切開：廠務只能改自己廠，其他廠只能查詢。第一階段只有一廠，一廠廠務名單見第 9 節；跨廠權限的確認見第 10 節。
- 廠務內不分權限級別。
- 系統自動處理的異動也記入異動紀錄，記為「系統」。

## 3. 系統架構

- 依 EC Portal 05 指南做成獨立站：自己的容器與資料庫（放在 NAS 10.11.1.40），共用 authentik／AD 登入，群組用 `Portal-<Feature>-*`，session cookie 與 compose project 名稱與 EC Portal 分開。
- **路由分兩類**：公開唯讀路由（查詢頁與其 API，不掛登入檢查）與維護路由（`/admin/*`，掛 OIDC 登入檢查，且須在廠務群組，例如 `Portal-Dir-Admins`；群組名稱放設定檔）。authentik 只服務維護路由，公開查詢不經過它。
- **公開查詢另寫一支查詢**，固定只回傳姓名、部門、職稱、分機、等級，不與維護頁共用查詢函式，避免日後加欄位時洩漏。
- **防爬取與紀錄**：公開查詢加簡單限流（同一 IP 超過門檻回 429）；只記 IP 與時間於網站日誌，不進異動紀錄。維護操作照舊記入異動紀錄。
- **網路**：只開內網；其餘（反向代理、自簽憑證）比照 D17 的做法，埠避開 EC Portal 的 8000／8443。
- 人員來源：Domino →（n8n 每日完整比對）→ 系統 API → 資料庫。比對流程複製自 `LlpupUEw4njAIlpn`，原流程（每天 08:00、只新增到 `email_mapping`）不改。
- 匯出：系統即時從資料庫取資料，呼叫 n8n 產 Excel（202 ＋ callback 模式）。
- EIP 由廠務手動上傳，貼牆表由廠務列印更換。已下載的檔案、已印出的紙本、已上傳的 EIP 檔都是當下的快照，不會自己更新。

## 4. 資料

### 4.1 紀錄類型
只有兩種紀錄：**人員**、**單位**。

- **人員**：來自 Domino 名冊，以 Email 識別（姓名有重複）。每人屬於一個部門。
  - 預設使用所屬部門的公用分機；有個人分機者個別覆蓋。
  - 「主管」不是另一種類型，而是一條檢查規則：職稱課長以上（含副理、經理、處長、廠長）必須有個人分機（見 5.2）。
- **單位**：非人員的分機，沒有 Email，不與 Domino 比對。包含：
  - 部門公用分機，例如製一組 211、噴一課 (A棟) 511／(M棟) 512。
  - 場所與專線，例如會議室、禮堂、守衛室、餐廳、機房、宿舍、無塵室、公用電話、緊急專線、總機、e-learning。
  - 一支分機一筆紀錄；有「列印名稱」，預設為單位名稱，可改（例如「噴一課 (A棟)」）。**同部門內列印名稱可以重複**，靠分機區分：貼牆表上皮技課 170／171、連續製程辦公室 262／263 就是各印兩列同名。只有「名稱與分機都相同」才視為重複紀錄。
- **位置**：照貼牆表。沒有掛部門的紀錄放在置頂區塊（緊急專線、總機、廠長、副廠長）；有掛部門的放在該部門下（例如 e-learning 615 在總務課）。
- **同部門下兩組共用一支分機**（製一組與製二組 211、製三組與製四組 221）：兩組各自是部門節點、各有單位紀錄、分機相同。列印時相鄰的兩列分機欄合併成一格，各列仍印名稱。
- 人員與單位在同一個維護頁，用類型篩選。

### 4.2 人員與 Domino
- Domino agent 目前回傳 cname、email、dep、supervisor。沒有工號；dep 只是名稱；主管只有姓名。職稱已請同仁在 API 開出，上線前完成，系統的職稱以 Domino 為準。
- 每人有「列入分機表」欄位（預設是）：
  - 不要求全員列入。外籍員工沒有分機（已確認）。
  - Domino Email 為 `f`＋數字者預設為「否」（預設規則，廠務可改，未經證實）。
  - 標為「否」者不出現在新進通知，也不算「Domino 有、系統沒有」的缺漏。
- 若能向 Domino 要到工號更好（見第 9 節）。

### 4.3 部門表
- 每廠一張，由該廠廠務維護。這是「分機表的顯示分組」，不是人事的正式組織架構。
- 依貼牆表展開（貼牆表的名稱接近 Domino，例如「噴乾一課」對「一廠噴乾一課」）。
- 層級：部、室、處同為第一層，其下為課，課下為組。不設「第一廠」這一層。
- 操作：
  - 新增、改名（底下人員自動跟著變）、同層排序（↑ ↓，列印版依此排列）。
  - 移動：連同子部門與底下人員一起搬到另一個上層（或最上層），分機表與列印版自動換位置；目的地有同名部門時擋下。
  - 停用：底下還有人員或單位時不能停用。
- 部門設定：
  - **預設分機**：新進人員自動帶入。部門有多支公用分機時（噴一課 A棟 511／M棟 512）由廠務選一支；沒有設定時，新進人員進待確認。
  - **號段**（例如合一課 210～219）：只做建議與提醒，見 4.4。
  - **列印**：最上層部門的欄（1～3）與欄內順序；底色（例如金技課、工智處下的單位用淺青色）；**「印標題列」**（預設是，在部門表頁每個部門各有一個勾選）。
- Domino 部門名稱對照：名稱相同自動對應；對不上的列為「未對應」，由廠務指定放到哪個部門或新增為部門，對應一次後記住。
- 若人事之後能提供部門代碼、上層部門，可一次匯入，之後改名不會被當成人員異動。第一版不依賴。

**一廠部門表（依貼牆表展開）**
- 置頂（無部門）：緊急專線、總機、廠長、副廠長
- 總經理室；廠長室 › 生管課；人事室
- 生產一部 › 合一課（製一組、製二組）、合二課（製三組、製四組）、合三課（製七組、S棟）
- 生產三部 › 合四課（製八組、L棟無塵室、ALPHA ROOM）
- 實驗工場；安全衛生室
- 生產二部 › 噴乾一課、液品課、成品課、乾燥課、精細課
- 品保部 › 品一課、品二課（含應用組）
- 技銷處 › 技銷處五部 › 金技課、皮技課、紙技課
- 環保部 › 環保課、環資課
- 廠務部 › 總務課（含餐廳、禮堂、會議室等單位）、原料課
- 環資管理處
- 工程管理暨智慧製造處 › 工智處一部一課、工程管理部、智慧製造部

### 4.4 分機號碼表
- 由廠務維護，與部門表在同一個維護站。這張表本身不印，但其中的空號會印在貼牆版上（見 7.2 第 4 條）。
- 欄位：分機號碼、所屬部門、等級（A/B）、狀態、備註。
- **等級**屬於分機號碼：同一支分機改一次，所有使用者跟著變。等級表示該分機能否撥打外線（2026-11-08 確認）。系統只記錄與列印，不控制交換機；實際撥號權限仍由交換機設定。
- **狀態**由系統計算：有人員或單位使用為「使用中」，沒有為「空號」。
- 有個人分機的人離職或調走，經廠務確認後，號碼回到所屬部門的空號；新進人員要個人分機時，系統列出該部門的空號供挑選。
- 所屬部門依部門號段自動帶入，可手動改。號碼指派到別的部門號段時提醒廠務，不擋。

**一廠號段（約定俗成，非正式規則）**
- 百位數對應最上層部門，十位數對應課；部、課主管多用該段的 x01 或 x10。
- 1xx 廠長、總經理室、廠長室、生管課、人事室、技銷處（15x～18x）；2xx 生產一部、生產三部、實驗工場（21x 合一課、22x 合二課、24x 合三課、25x 合四課、26x 實驗工場）；3xx 品保部；4xx 安全衛生室；5xx 生產二部；6xx 廠務部；7xx 環保部；8xx 環資管理處；9xx 工程管理暨智慧製造處。
- 現有例外：生產三部用 2xx；乾燥課與成品課共用 541／542；楊梓盛（智慧製造部）用 924；總機 613 在總務課號段但列印置頂；23x 未使用（舊 EIP 檔中精細課曾用 230～232，僅供參考）。
- 現有空號：614（總務課）、815～819（環資管理處）。

### 4.5 資料模型（建議）
- `plants`：廠區（名稱、市話、簡碼、檔尾文字）
- `departments`：id、plant、parent_id、name、sort、active、default_ext、ext_range_from、ext_range_to、print_column（1～3，只對最上層）、print_order、fill_color
- `dept_map`：plant、domino_dept_name → department_id
- `ext_numbers`：plant、ext、department_id、grade（A/B）、note；狀態不存，由使用紀錄計算
- `extensions`（人員與單位）：id、plant、type（人員／單位）、name、print_name（單位用）、email（人員才有）、department_id（空＝置頂）、title、ext、personal_ext（人員是否有個人分機）、in_directory（列入分機表）、hide_in_print（不列）、sort、active、note、updated_at、updated_by
- `domino_roster`：email、name、dep、title、supervisor、active、last_seen
- `domino_changes`：kind（新進／調部門／職稱變動／離職）、email、from_dep、to_dep、from_title、to_title、status（待確認／已自動處理／已套用／略過／已還原）、before／after（還原用快照）、run_id（哪一次比對）、detected_at
- `audit_log`：誰（含系統）在何時改了什麼

## 5. 上線後的維護（Domino 異動）

第一版資料建立後（見第 8 節），人員異動以 Domino 為唯一來源。系統每天比對，能判斷的自動處理並通知，判斷不了的交廠務確認。換分機、新增會議室等 Domino 看不出來的變動，由廠務直接在維護頁修改。

### 5.1 每日比對
n8n 每天取 Domino 完整名冊，與 `domino_roster` 比對，產生新進、調部門、職稱變動、離職，交給系統 API 依 5.3 處理。

### 5.2 主管判斷
- 依 Domino 職稱判斷，課長以上視為主管。
- 主管應有個人分機；系統不會替主管自動套用部門公用分機。
- 職稱為課長以上卻沒有個人分機時，提醒廠務（也列入列印前檢查）。

### 5.3 自動處理與待確認
| 情況 | 自動處理＋通知 | 交廠務確認 |
|---|---|---|
| 新進 | Email 為 `f`＋數字：設為不列入，不通知。部門對得上、非主管、部門有預設分機：加入並用預設分機。 | 部門對不上；部門沒有預設分機；主管（含空降）。 |
| 離職 | 用公用分機者：停用。 | 有個人分機者（貼牆表上這一列的名稱會變空白、號碼仍印出，分機可能交接）；確認後號碼回到空號。 |
| 調部門（含升遷） | 用公用分機、新部門對得上、非主管、新部門有預設分機：換部門，分機改為新部門的預設分機。 | 有個人分機者；調動後成為主管、但沒有個人分機者。 |
| 原地升遷 | — | 職稱變為主管，且沒有個人分機。 |
| 同一批人同時換到同一新部門 | — | 視為可能的部門改名，見 5.4。 |

**新進的部門對不上時，會產生兩筆待確認，依序處理：**
1. **部門**：Domino 部門名稱在部門表裡沒有對應。廠務指定放到哪個既有部門，或新增為部門（放在最上層，之後可用「移動」調整）。對應一次後系統記住，之後同名部門自動對上。
2. **人員**：部門處理完，這位新進才產生第二筆「補分機」。部門有預設分機就帶入，沒有就由廠務選（個人分機或新增單位）；存檔後才加進「人員與單位」。

兩筆分開處理，因為部門決定後，分機才有地方放。

### 5.4 部門改名
Domino 只看得到「部門名稱變了」，分不出是人調動還是部門改名，所以改名時會同時出現一批異動。系統把它們列在一起，廠務到部門表改名後**整批套用**。

### 5.5 保護機制
- **異常暫停**：單次比對離職超過 5 人或 3%，該次全部改為待確認（防 Domino API 回傳不完整名單）。第一階段只有一廠，分母就是一廠人數；多廠後的算法見第 10 節。
- **可復原**：自動處理的每一筆記入異動紀錄，可一鍵還原。

### 5.6 通知
- 每天一封彙整信給該廠廠務，分「已自動處理」與「待你確認」兩段（不逐筆寄信）。
- 維護頁鈴鐺＋異動收件匣。

## 7. 匯出

### 7.1 EIP 上傳檔
- 欄位：廠區／分公司、部門（以 `\` 分層）、姓名、職稱、市話、分機、簡碼、備註。
- 列出該廠所有啟用且「列入分機表」的人員與單位；「不列」只影響列印版。
- 上傳會覆蓋整廠：匯出前提醒資料是否最新，並顯示匯出時間。

### 7.2 列印版 1（貼牆版）
對齊現有貼牆表，程式依下列規則執行（2026-11-07 定案）。判斷只用：紀錄類型、所屬部門、分機、是否有個人分機、列印名稱、職稱、排序、不列、等級。

1. 取該廠啟用中、「列入分機表」為是、未標「不列」的紀錄。
2. 單位紀錄：印一列「列印名稱＋分機」。
3. 人員紀錄：有個人分機，印一列「姓名 職稱＋分機」；使用部門公用分機，不印（由單位列代表）。
4. 空號：分機號碼表中狀態為「空號」、且有所屬部門的分機，印一列「名稱留空、只有分機與等級」，放在所屬部門內，位置依分機號碼接在前一支分機後面。沒有所屬部門的空號不印。（貼牆表現況：614 在總務課、815～819 在環資管理處。）
5. 沒有部門的紀錄放在最前面的置頂區塊。
6. 以最上層部門（部／室／處）為區塊，整塊放同一欄、不拆欄。每個最上層部門有「欄（1～3）」與「欄內順序」，由廠務設定。
7. 區塊內順序：部門標題列 → 該部門自己的人員與單位，統一依「排序」（沒設排序時，預設人員在前、單位在後；人員內依職稱順序：廠長、副廠長、處長、部長、經理、副理、課長、副課長、組長、無職稱，再依分機）→ 子部門（依排序，遞迴套用本條）。
8. 部門標題列：第一層黃底、三格合併、字間加全形空格（例如「生　產　一　部」）；第二層以下淺色底、三格合併；部門可另設底色。部門有「印標題列」設定（在部門表頁維護）：關閉時只印底下的單位列，例如製一組、製七組、S棟這類只有一個同名單位的組。底下有子部門、或有個人分機的人員時，一律印標題列，設定無效。
9. 同一區塊內，相鄰的列使用同一支分機時（製一組與製二組 211、製三組與製四組 221），分機欄合併成一格，各列仍各印名稱與等級，和貼牆表的合併儲存格相同。不相鄰的相同分機（例如成品課與乾燥課的 541／542）各印各的。
10. 同一分機出現在不同部門時各印一列；要隱藏其中一列就標「不列」。
11. 等級欄取自該廠該分機的等級。欄頭為「單位名稱／分機號碼／等級」，標楷體 12 粗體、置中。
12. 標題為「○廠各單位分機號碼表」，修訂日期預設為匯出日；檔尾文字取自廠區設定（各廠總機、傳真、辦事處與撥號規則：公司 #80、一廠 #81、二廠 #82、三廠 #83、四廠 #84、上海明德 #80→888→66）。
13. A4 直式、縮放 80%、三組並排、一頁印完。任一欄超過約 52 列時警告廠務；另提供「自動平衡欄高」（以最上層部門為單位，依序填入最短的欄）。

**列印前檢查**（產生警告，不擋匯出）
- 職稱為課長以上，卻沒有個人分機。
- 人員使用部門公用分機，但該部門沒有單位紀錄（印不出來）。
- 同一分機出現在不同部門而都沒標「不列」。
- 有分機的單位或人員所屬部門沒有排序、沒有指定欄。
- 任一欄過長。

### 7.3 列印版 2（新風格）
- 依最上層部門分區塊卡片，分機放大；單位與人員用顏色區分；檔尾帶跨廠撥號。空號不印。
- 橫式（A4 橫向，4 欄）與直式（A4 直向，3 欄），匯出時選方向，Excel 的紙張方向與欄數同步設定。
- **一頁放完**：系統依資料量自動調整列高與字級，找出這一頁放得下的最大值（列高最小 13px，約 6～7pt）；放不下時才自動接第二頁，並在列印前檢查提醒。一廠目前橫式約 16px、直式約 18px。
- **分欄由廠務調整**：在「列印版面」的新風格版頁籤，每個最上層部門可以指定放第幾欄與欄內順序，橫式與直式各自記錄；也可以按「自動平衡欄高」，依序平均分到各欄。
